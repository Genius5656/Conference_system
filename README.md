# Портал «Конференции.РФ»

Информационная система бронирования помещений для проведения Всероссийских
конференций: аудитории, коворкинги и кинозалы.

Пользователь регистрируется, формирует заявку на нужное помещение (дата, время,
способ оплаты), отслеживает её статус в личном кабинете и оставляет отзыв после
завершения мероприятия. Администратор видит все заявки, фильтрует их и меняет
статусы.

---

## Стек технологий

| Слой | Технологии |
| --- | --- |
| Фронтенд | HTML5, CSS3, JavaScript (ES2017+, без фреймворков) |
| Бэкенд | Python 3.8+, FastAPI, SQLAlchemy 2.0 (ORM), Pydantic 2 |
| База данных | PostgreSQL 14+ (нативные типы `ENUM`, внешние ключи, ограничения `CHECK`) |
| Безопасность | bcrypt (хеши паролей), JWT в httpOnly-куке (PyJWT) |
| Инструменты | pytest, httpx, Pillow (оптимизация изображений), Graphviz (ER-диаграмма) |

Все зависимости проекта перечислены в файле [`requirements.txt`](requirements.txt).

## Руководство по запуску проекта

### Шаг 1. Требования

* Python 3.8 и новее;
* PostgreSQL 14 и новее (или Docker для запуска через `docker-compose`);
* (необязательно) Graphviz — только для перегенерации ER-диаграммы.

### Шаг 2. База данных

**Вариант A — уже установлен PostgreSQL:**

```bash
sudo -u postgres psql -c "CREATE USER conference WITH PASSWORD 'conference';"
sudo -u postgres psql -c "CREATE DATABASE conference_system OWNER conference;"
```

**Вариант B — Docker:**

```bash
docker compose up -d
```

### Шаг 3. Виртуальное окружение и зависимости

```bash
cd conference_system
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 4. Настройки

```bash
cp .env.example .env
```

Откройте `.env` и укажите свои значения:

```dotenv
APP_SECRET_KEY=<случайная строка, например из `openssl rand -hex 32`>
DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5432/conference_system
ADMIN_LOGIN=Conf2027
ADMIN_PASSWORD=Demo77
```

Если создавали отдельного пользователя БД (вариант A), URL будет таким:

```dotenv
DATABASE_URL=postgresql+psycopg2://conference:conference@localhost:5432/conference_system
```

### Шаг 5. Инициализация базы данных

Схема создаётся и наполняется стартовыми данными автоматически при первом
запуске приложения. При необходимости инициализацию можно выполнить вручную:

```bash
python scripts/init_db.py
```

Создаются таблицы `users`, `rooms`, `bookings`, `reviews`, перечисления
PostgreSQL, 5 помещений справочника и учётная запись администратора.

### Шаг 6. Запуск приложения

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
# либо
python -m app.main
```

Откройте в браузере: <http://127.0.0.1:8000/>

| Адрес | Назначение |
| --- | --- |
| `/index.html` | Главная страница с каталогом помещений |
| `/register.html` | Регистрация пользователя |
| `/login.html` | Вход в систему |
| `/bookings.html` | Личный кабинет: мои заявки и отзывы |

## Тесты

```bash
pytest -q
```

Тесты используются для проверки основных сценариев (31 тест):

* регистрация со всеми правилами валидации и обработка дубликата логина;
* вход/выход, защита маршрутов, права администратора;
* создание заявки (справочник и произвольное помещение, прошедшие даты, способы оплаты);
* жизненный цикл статусов `new → assigned → completed` и запрет недопустимых переходов;
* отзыв доступен только после завершения мероприятия и только один раз;
* фильтрация заявок в панели администратора.

Перед каждым тестом схема базы пересоздаётся, поэтому тестовый набор
детерминирован. URL подключения задаётся переменной `DATABASE_URL`.

## Основные возможности API

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Регистрация (логин, пароль, ФИО, телефон, e-mail) |
| `POST` | `/api/auth/login` | Авторизация, установка httpOnly-куки |
| `POST` | `/api/auth/logout` | Выход из системы |
| `GET` | `/api/auth/me` | Текущий пользователь |
| `GET` | `/api/rooms` | Каталог помещений |
| `GET` | `/api/bookings` | Мои заявки (с отзывами) |
| `POST` | `/api/bookings` | Создание заявки (статус «Новая») |
| `POST` | `/api/bookings/{id}/reviews` | Отзыв о мероприятии (1–5 баллов) |
| `GET` | `/api/admin/bookings` | Все заявки + фильтры (статус, логин, помещение, даты, страница) |
| `PATCH` | `/api/admin/bookings/{id}` | Смена статуса заявки |
| `GET` | `/api/admin/stats` | Сводная статистика |
| `GET` | `/api/health` | Проверка работоспособности и БД |

## Правила валидации

| Поле | Правило |
| --- | --- |
| `login` | только латиница и цифры, 6–32 символа, уникален |
| `password` | 8–72 символа, хранится в виде bcrypt-хеша |
| `full_name` | только кириллица и пробелы |
| `phone` | формат `8(XXX)XXX-XX-XX` (на форме — маска ввода) |
| `email` | стандартный формат адреса, приводится к нижнему регистру |
| `event_date` | не раньше сегодняшнего дня |
| `payment_method` | только `onsite` (очная оплата) или `sbp` (перевод по СБП) |
| `rating` | целое от 1 до 5 |

Ошибки отображаются под соответствующим полем формы и продублированы общим
сообщением над кнопкой отправки.

## Статусы заявки

| Код | Отображение | Допустимые переходы |
| --- | --- | --- |
| `new` | Новая | → Мероприятие назначено, → Завершено |
| `assigned` | Мероприятие назначено | → Завершено, → Новая |

## Дизайн

Вёрстка выполнена по «Руководству по стилю»:

* цвета: голубой `#007bff`, тёмно-синий `#0d47a1`, серый `#6c757d`,
  фон `#f8f9fa`, выделяющий `#ffffff`;
* шрифт PT Sans: H1 — 36px Bold, H2/H3 — 24/18px Bold, текст — 16px,
  вспомогательный — 12px Italic;
* адаптивная вёрстка: десктоп, планшет и мобильные устройства (целевой
  разрешения 390×844), бургер-меню на узких экранах;
* микроанимации: появление блоков при прокрутке, подъём карточек, пульсация
  статуса «Новая», спиннеры загрузки, всплывающие уведомления, индикация
  ошибок; анимации отключаются при `prefers-reduced-motion`.
